The first call generates the standard displacements and, if the default boundary conditions have periodic axes, the displacements for kernels lattice-summed along those axes. Lists for any other set of lattice-summed axes are built on their first request (get_disp, get_disp_images), which SeparatedConvolution makes when it is constructed.

◆ bmax_axes()

template<std::size_t NDIM>
static std::array< int, NDIM > madness::Displacements< NDIM >::bmax_axes ( )
inlinestatic

The bound on |l_d| for the displacements l that do_apply visits at level n, per axis.

The blocks of the non-standard form decay with the real-space distance l_d h_d, so a narrow axis needs more boxes to reach the same decay as a wide one: a fit term unresolved on the long axis (which is what makes the operator act on it at level n) is smooth across the boxes of a short axis, where its block falls off only as exp(-a (l h)^2). Hence bmax_d = ceil(bmax_default * w_max / w_d): bmax_default on every axis of a cube, (4, 4, 23) in a 100x100x18 cell, where an isotropic 4 leaves the Coulomb potential of a neutral chain 1.3e-4 off the analytic result at eps 1e-6 (1e-5 with the per-axis bound). The extra displacements are only norm-checked: for a decaying kernel the shell-wise stop in do_apply ends the loop at the same real distance as before.

Cost: the lists hold prod_d (2 bmax_d + 1) keys (up to 2x more per lattice-summed axis), the periodic ones for every level, so they grow with the aspect ratio along every short axis. Measured in 3D with two short periodic axes and a 100-bohr free one: 18x18x100 -> 4.4e6 keys, 170 MB, 0.9 s to build; 5x5x100 -> 5.1e7 keys, 1.9 GB, 13 s, paid on every set_cell that changes the shape. Nothing limits the reach beyond the overflow guard below: the boxes past the shell stop are never visited, but how to drop them safely is not known (a Dirac solver resolving the nuclei refines to level ~30 where the kernel is local on every axis). In 6D the standard list alone would hold (2 bmax_d + 1)^6 keys, 7e7 for a 5.6:1 cell, so non-cubic cells are not practical there (and 6D is not used in periodic settings).

orders by the distance to the nearest non-home image: least distance between the boxes, then boxes, then the distance between the box centers. The last breaks the tie among the displacements one box from an image, which are all at least distance 0: the narrowest summed axis comes first, and its block is the operator's largest (SeparatedConvolution::norm_bound visits the leading image-adjacent run).

◆ periodic_lists

template<std::size_t NDIM>
std::array<std::atomic<PeriodicLists*>, (std::size_t(1) << NDIM)> madness::Displacements< NDIM >::periodic_lists {}
inlinestaticprivate

the lists for each set of lattice-summed axes, indexed by the axes' bitmask; a slot is filled on the first request for its axes (see periodic()) and published through the atomic once complete, so lookups take no lock. Sorting the lists with the metric of the axes they are requested for is what makes the shell-wise screening of FunctionImpl::do_apply sound: a list sorted for a superset of the kernel's axes would place a displacement wrapped along an axis the kernel does not sum next to the source, where for that kernel it is a cell away. A set holds every level's list in each order it was asked for (for NDIM = 3 up to (4 bmax + 1)^3 keys per level, some ten MB per order), so a process that uses operators summed along several different axis sets pays that per set; before, one set served them all.
